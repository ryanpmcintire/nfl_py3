# NFL ATS

NFL ATS is a reproducible research and prediction pipeline for estimating which
side of an NFL point spread will cover. It uses maintained
[nflverse](https://nflverse.nflverse.com/) datasets instead of scraping HTML,
constructs every feature strictly from information available before kickoff,
and evaluates model choices with nested chronological walk-forward tests.

## Principles

- One canonical row per game, keyed by nflverse `game_id`.
- Immutable, timestamped source snapshots with provenance manifests.
- A single sign convention: positive margins and spreads favor the home team.
- Explicit chronological development, validation, and outer-test periods; a
  model may only train on games before the week it predicts.
- The market is a baseline, not a feature we quietly declare victory over.
- The project's primary goal is **forced-pick classification accuracy against
  a 50% coin flip**: the pool requires a pick on every game and never allows a
  pass. Probability calibration is a first-class output because it feeds that
  pick; vig-aware paper decisions (including an optional PASS action some
  research commands can emit) are a secondary diagnostic, not the target the
  project is judged against, and ROI/Kelly sizing are exploratory paper
  analysis only.
- Every published card passes an independent, fail-closed prediction-safety
  contract before it is written.
- Raw data and model artifacts never belong in Git; only the deliberately
  published, human-readable current card is tracked.

## Data semantics

```text
home_margin = home_score - away_score
ats_margin  = home_margin - spread_line
```

In nflverse, a positive `spread_line` means the home team is favored. Therefore:

- `ats_margin > 0`: home covered
- `ats_margin < 0`: away covered
- `ats_margin == 0`: push

Historical nflverse lines are closing lines. Live lines can move, so every
refresh creates an immutable snapshot with a UTC fetch timestamp. A backtest
must not pretend a closing line was available earlier than it really was.

## Quick start

The project requires Python 3.12 and uses
[uv](https://docs.astral.sh/uv/) for Python and dependency management.
This working copy already has a portable uv executable at `.tools/uv.exe`; it
does not add `uv` to the system `PATH`. From PowerShell in the repository, run:

```powershell
.\.tools\uv.exe sync --all-groups
.\.tools\uv.exe run nfl-ats doctor
```

On a fresh clone where `.tools/uv.exe` does not exist, install uv first (for
example, `winget install --id astral-sh.uv -e`), restart the terminal, and use
`uv` in place of `.\.tools\uv.exe` below.

The weekly production pipeline -- ingest, build every feature table the active
model needs, backtest to confirm the historical match, predict the week, and
publish the card -- is one command. Full step list, measured timing, and the
manual fallback if the command breaks live in `docs/ops_runbook.md`:

```powershell
.\.tools\uv.exe run nfl-ats weekly-run --season 2026 --week 1 --record-decisions
```

Steps 1-7 (the card path) fail closed: **no publish happens unless the
synchronization assertion passes**, so a broken step aborts before a
half-built card reaches the public site. Steps 8-11 append prospective 2026
research evidence after the publish and are optional -- a failure there is
reported but does not undo the publish. Add `--dry-run` to print the plan
without running it, `--skip-ingest` to reuse snapshots already on disk, and
`--refresh-player-data` to pick up newer player/PBP snapshots. Pass
`--record-decisions` only for the real Tuesday lock; both recorders it feeds
separately refuse to write outside a 7-day window of that week's kickoff, so a
rehearsal run cannot reach a real ledger by accident.

The pre-lock wiring check is deliberately static and millisecond-scale:

```powershell
.\.tools\uv.exe run --no-sync python scripts\lockday_rehearsal.py
```

It compares all active challenger registrations with the CLI result-key map
and the verifier's dynamic coverage contract without importing the model stack,
executing recorders, or touching ledgers. The former production-sized replay is
available only as explicit slow diagnostics with `--full-replay`; it is not the
routine readiness check.

Each run also writes `prediction_safety.json`. It independently recomputes
probability bounds, picks, vig and no-vig math, edges, prices, training
cutoffs, and model-input coverage. An inconsistency aborts the command instead
of publishing a plausible-looking card. It also writes the forced-pick
`pool_card.csv`/Markdown file ranked by confidence for ATS pools -- the
deliverable the pool actually scores, since it requires a pick on every game.
A separate, older `predict` command (the compact `market_context` model, not
part of the `weekly-run`/`margin-predict` production path) supports
`--freeze` for a deliberately declared prospective evaluation window near a
decision time; frozen records are immutable, refuse retrospective or
unverifiable rows, and are revalidated when read. That same `predict` command
also emits a vig-aware paper action that may remain `PASS` -- a secondary
research diagnostic, never the forced-pick card the pool grades.

The public dashboard is the GitHub Pages site built from `docs/` by
`nfl-ats publish-predictions` / `nfl-ats publish-board`: this week's card,
the model, row-level History, and what we've learned, in plain words. It reads generated
artifacts without modifying them.

The same four-page site can run locally or on a server as a read-only,
unprivileged container. See [dashboard container deployment](docs/container_deployment.md)
for the one-command Compose path, the narrow build-context contract, and server
exposure guidance.

Historical and weekly headline pages share `artifacts/active_ats_model.json`.
That atomic manifest links one exact evaluation artifact to one matching weekly
forecast, method, feature profile, regressor, Ridge strength, calibration policy,
and feature-table hash. A forecast with no exact historical match is marked
`UNLINKED` and cannot silently replace the synchronized site default. The
"Active model and grades" section above is regenerated from this manifest
every time `nfl-ats handoff` or `nfl-ats publish-predictions` runs.

If a synchronized `margin-predict` forecast is already on disk and only the
published card needs to change (for example, a fresh arrest snapshot but
nothing upstream), the last two `weekly-run` steps are enough on their own:

```powershell
.\.tools\uv.exe run nfl-ats ingest-player-arrests
.\.tools\uv.exe run nfl-ats publish-predictions
```

The arrest ingest refreshes the production policy's fail-closed source. The
publisher refuses a stale arrest snapshot, an unlinked card, or a model-ID
mismatch. It updates this README's marked sections and `CURRENT_PREDICTIONS.md`
from the same active artifact and registries, so all of it moves together in
one commit.

Current book-specific odds are optional. After obtaining a provider key, set it
for the current PowerShell session and archive a timestamped observation:

```powershell
$env:THE_ODDS_API_KEY = "your-key"
.\.tools\uv.exe run nfl-ats odds-ingest
.\.tools\uv.exe run nfl-ats odds-summary
```

The key is never written to an artifact. A separate no-key command downloads
the public Spreadspoke/Kaggle archive, preserves its source ZIP and license,
normalizes its reported closing spreads, and audits them against nflverse:

```powershell
.\.tools\uv.exe run nfl-ats market-backfill
```

That archive has one reported close per game, not timestamped quote movement.
It is useful for source comparison but is never presented as a 24-hour or
Tuesday-morning line. Local timestamped collection supplies that future history.

A second no-key command downloads a free CC BY-NC 2025 sample containing the
market opener plus reported closing lines and prices from nine named books for
spreads, moneylines, and totals:

```powershell
.\.tools\uv.exe run nfl-ats market-open-close-backfill
```

It normalizes 17,100 outcome quotes across 285 games. The source distinguishes
open from close but supplies no quote timestamps, so it is suitable for
open-to-close movement research—not a claim about the line available at an
arbitrary Tuesday or 24-hour decision point.

## Commands

Run `.\.tools\uv.exe run nfl-ats <command> --help` for full, always-current
options; this is a categorized map of what exists, not a copy of every flag,
and it can drift the way the rest of this section used to -- treat `--help`
as authoritative if the two ever disagree.

**Diagnostics**
`doctor` (runtime and data health), `smoke-source` (nflverse source/schema
availability).

**Weekly production pipeline**
`weekly-run` (the one command, `docs/ops_runbook.md`), `ingest-player-arrests`,
`publish-predictions`, `publish-board`, `refresh-picks` (recompute picks at
the frozen Tuesday grading lines any time before kickoff, `docs/late_week_refresh.md`),
`handoff [--check]` (refresh, or verify the freshness of, `HANDOFF.md` and
this README's generated blocks).

**NFL data ingestion**
`ingest`, `pbp-ingest`, `depth-ingest`, `player-ingest`, `player-value-ingest`,
`participation-ingest`, `role-actions-fetch` (immutable, timestamped nflverse
snapshots); `odds-ingest`, `odds-backfill`, `odds-summary` (point-in-time book
quotes, requires `THE_ODDS_API_KEY`); `market-backfill`,
`market-open-close-backfill` (free historical/opener-close archives, no key).

**NFL feature building**
`build-features`, `build-pbp-features`, `build-qb-features`,
`build-player-features`, `build-participation-features`,
`build-learned-availability-features` -- each adds leak-safe state on top of
the last, from the canonical table through PBP, QB, player, participation, and
learned-availability layers.

**NFL model evaluation and research**
`backtest`, `margin-backtest`, `margin-predict`, `predict`, `predict-close`,
`nested-evaluate` (walk-forward evaluation and weekly scoring);
`opener-evaluation` (the pool primary-goal measurement: the frozen active
model at Tuesday openers vs. closes); `player-ablation`,
`participation-ablation`, `availability-ablation`, `player-model-selection`,
`market-decomposition`, `key-number-calibration`, `pool-card-at-lines`,
`dependence-audit`, `drift-report`, `experiment` (feature-family, calibration,
and diagnostic research tooling); `clv-score`, `clv-ledger`, `clv-pilot`,
`clv-sign-test`, `prospective-record`, `prospective-score`, `anytime`
(closing-line-value and prospective-tracking tooling); `rotation`,
`weak-signals` (the confirmation-window and weak-signal registries the
Research state section above summarizes).

**College football (CFB) replication, XLG series**
`cfb-ingest`, `cfb-summary`, `cfb-build-features` (ingest and build the CFB
benchmark table); `cfb-benchmark`, `cfb-sensitivity-audit`,
`cfb-role-replication`, `cfb-absence-separation`, `cfb-role-benchmark`,
`cfb-variance-benchmark` (the frozen CFB-only replication battery).

Reproduce the evaluator positive-control audit—which first verifies the exact
active prediction stream and then measures recovery of known synthetic
0.5-, 1-, and 2-point signals—with:

```powershell
.\.tools\uv.exe run python scripts\sensitivity_audit.py
```

The output is a timestamped, ignored directory under
`artifacts/sensitivity_audits/`; it cannot activate or publish a model.

## Repository layout

```text
src/nfl_ats/       application and modeling code
tests/             deterministic unit and integration tests
docs/              architecture, data, and modeling decisions
data/raw/          ignored immutable source snapshots
data/pbp/raw/      ignored, season-partitioned PBP snapshots
data/players/participation/raw/ ignored participation snapshots
data/quarterbacks/depth/raw/ ignored timestamped QB depth-chart snapshots
data/cfb/          ignored immutable CFB (XLG series) source snapshots
data/market/raw/   ignored timestamped book/line/price observations
data/market/historical/raw/ ignored source archives and normalized reported closes
data/market/historical/open_close/raw/ ignored 2025 opener/multi-book close snapshots

registry/          tracked weak-signal and rotation registries (JSON)
```

## Development

```powershell
.\.tools\uv.exe run ruff format --check .
.\.tools\uv.exe run ruff check .
.\.tools\uv.exe run mypy src
.\.tools\uv.exe run pytest
```

`pytest` runs distributed across all cores by default (`-n auto` via
`pytest-xdist`, measured ~37s for the full suite vs ~216s serial; pass `-n0`
for a serial debugging run). The suite is order-independent — verified with
repeated parallel runs before the default was switched.

See [docs/architecture.md](docs/architecture.md),
[docs/data.md](docs/data.md), [docs/modeling.md](docs/modeling.md), and the
[performance contract](docs/performance.md) for the design, leakage boundaries,
and evaluator budgets. The full prioritized backlog, including simulation and
pool moonshots, lives in [ROADMAP.md](ROADMAP.md). New development sessions
should begin with [HANDOFF.md](HANDOFF.md). The agent and repository hooks refresh
and stage it (and this README's generated blocks) automatically before commits
and enforce freshness before a `master` push; `nfl-ats handoff --check` is
available for diagnostics.

## Responsible use

Sports markets are noisy and efficient. Backtest performance is not a promise
of future profit. Track the exact line, price, book, and decision timestamp;
include pushes and vig; report uncertainty; and never wager money you cannot
afford to lose.
