## Update 2026-11-03 (tape analysis built)
Done: scripts/sky04_tape_lag.py (ruff clean; `--selftest` runs the in-memory planted-lag check, nothing saved). Observation time = midpoint of request_sent and response_received; change time = provider lastModified when it advanced, else the bracket (previous poll, this poll); resolution = median poll gap (8.5 s).
Estimands declared before any estimate. (1) Provider lag d: observation delay D = observation time minus lastModified at each event-level lastModified advance; D = d + U(0, poll gap), so d_hat = median(D) - gap/2, SE = gap/(2 sqrt n). (2) Book lead-lag: for each tape line change old->new, the same old->new change of another book in data/market/raw/*odds-gap-private/quotes.parquet (source_scan_at_utc), nearest in time within the tape span; lag bracket = [scan before - T_hi, scan after - T_lo], reported as median lag with bracket width. Odds Gap has no per-book update stamp, so its resolution is the scan separation (minutes), not sub-minute; Bovada's own tape is the only sub-minute series.
Minimum sample (derived, no tuned threshold): 95% CI half-width no larger than one observation's own quantisation sd (gap/sqrt 12): n_min = ceil((1.96 / (2/sqrt 12))^2) = 12 lastModified advances. Lead-lag per book: n_min = ceil((1.96 sd / (width/sqrt 12))^2) from that book's own lag spread sd and bracket width; below it the status is below_minimum_sample and no estimate is reported or recorded.
